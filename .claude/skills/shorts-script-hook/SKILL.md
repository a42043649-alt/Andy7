# 숏폼 대본 + 훅

숏폼은 첫 3초에 스와이프 여부가 갈린다. 그래서 대본은 "훅 → 전개 → 마무리" 순서로 쓰되, 훅을 가장 오래 고민한다. 정보를 다 말해주는 것보다 **끝까지 보게 만드는 이유**를 앞에 두는 게 핵심이다.

## 절차

1. 입력 파악: 주제, 타깃 시청자, 플랫폼, 목표 길이(기본 30초). 빠진 건 합리적으로 가정하고 가정 내용을 한 줄로 밝힌다.
2. **훅 3안**을 서로 다른 유형으로 쓴다 (아래 유형표). 각 안은 한 문장, 말로 읽어 3초 안.
3. 가장 강한 안을 추천하고 이유를 한 줄로 쓴다.
4. 선택된 훅으로 본문을 쓴다. 시간 배분 기준 (30초 영상):
   - 0–3초 훅 / 3–8초 문제·공감 / 8–25초 핵심 3포인트 이내 / 25–30초 마무리+CTA
5. 한 줄 = 한 장면이 되도록 짧게 끊는다. 한 줄은 15자 안팎, 최대 2줄 자막으로 읽힐 길이. (다음 단계 스토리보드가 이 줄을 그대로 장면으로 쓴다.)
6. 영상 말미는 첫 장면으로 자연스럽게 이어지게 하면 루프 재생이 늘어난다 — 가능하면 적용.

## 훅 유형

| 유형 | 형태 | 예 |
|---|---|---|
| 결과 먼저 | 결말을 던지고 과정을 보여줌 | "이 한 줄로 월 12만 원 아꼈어요" |
| 질문/도발 | 통념을 뒤집음 | "아직도 이렇게 설거지해요?" |
| 숫자·리스트 | 개수 약속 | "회사에서 절대 말하면 안 되는 3가지" |
| 공감 | 상황 지목 | "퇴근하고 아무것도 하기 싫을 때" |
| 호기심 | 정보 간극 | "이거 모르면 매달 손해 봅니다" |

과장·허위 약속은 쓰지 않는다. 훅이 약속한 것은 영상 안에서 반드시 회수한다 (안 그러면 이탈과 신고가 늘어난다).

## 출력 형식 — `script.md`

```markdown
# <영상 제목(작업용)>
- 플랫폼: / 목표 길이: / 타깃: / 가정:

## 훅 후보
1. [유형] "..."
2. [유형] "..."
3. [유형] "..."
추천: N번 — 이유

## 대본
| # | 시간 | 내레이션/자막 | 비고(화면 아이디어) |
|---|---|---|---|
| 1 | 0–3 | ... | ... |

## CTA
- ...(팔로우/저장/댓글 유도, 하나만)
```

CTA는 하나만 쓴다. 여러 개를 요구하면 아무것도 안 한다.
